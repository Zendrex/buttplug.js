---
title: Commands
description: Control device outputs (vibration, rotation, position, and more)
---

Output methods on [`Device`](/docs/client/device) are async. They build protocol messages, map normalized values to each feature's device range, and reject with `DeviceError` when the capability is missing.

```ts
if (device.canOutput("Vibrate")) {
  await device.vibrate(0.5);
}
```

**Value scale:** normalized **0–1** floats. The library maps to each feature's device range internally (so `0.5` becomes the midpoint of whatever range the server reports — `50` on a 0–100 device, `10` on a 0–20 device). Position `duration` is in **milliseconds**.

For repeating waveforms (pulse, wave, custom ramps), use the [PatternEngine](/docs/patterns) instead of manual timers.

## Scalar outputs

`vibrate`, `oscillate`, `constrict`, `spray`, `temperature`, and `led` accept either one number for **all** actuators of that type, or a `FeatureValue[]` for per-motor control.

### Uniform intensity

```ts
await device.vibrate(0.75);
await device.oscillate(0.4);
await device.led(1);
```

### Per feature

```ts
await device.vibrate([
  { index: 0, value: 0.3 },
  { index: 1, value: 1 },
]);
```

`index` is the feature index from `device.features.outputs`, not the device index.

| Method | Output type |
| --- | --- |
| `vibrate()` | `Vibrate` |
| `oscillate()` | `Oscillate` |
| `constrict()` | `Constrict` |
| `spray()` | `Spray` |
| `temperature()` | `Temperature` (signed: heat / cool) |
| `led()` | `Led` |

Gate with `device.canOutput("Vibrate")` (or the matching type) before calling.

## Rotation

`rotate()` supports a single motor or multiple motors with direction.

```ts
// All rotation features at 60% speed
await device.rotate(0.6);

// Single motor, counter-clockwise
await device.rotate(0.6, { clockwise: false });

// Per motor
await device.rotate([
  { index: 0, speed: 0.5, clockwise: true },
  { index: 1, speed: 0.8, clockwise: false },
]);
```

Uses `RotateWithDirection` when the device supports it; otherwise `Rotate`. Check `device.canRotate` first.

## Position

Linear actuators need a target position and, on the uniform overload, a movement duration.

```ts
await device.position(0.8, { duration: 500 });

await device.position([
  { index: 0, position: 1, duration: 300 },
  { index: 1, position: 0.2, duration: 600 },
]);
```

Uses `HwPositionWithDuration` when available, else `Position`. Check `device.canPosition` first.

## Raw output

For advanced cases, send a typed `OutputCommand` to a specific feature. Unlike the typed methods, `output()` is the raw protocol escape hatch — `Value` is in the feature's **device range** (integer), not normalized 0–1:

```ts
await device.output({
  index: 0,
  command: { Vibrate: { Value: 50 } }, // device-range integer
});
```

See [`Device.output`](/docs/client/device#output) and [`OutputCommand`](/docs/client/types#outputcommand).

## Stopping

### One device

```ts
await device.stop(); // all features

await device.stop({ outputs: true, inputs: false }); // outputs only

await device.stop({ featureIndex: 0 }); // one feature
```

### All devices on the client

```ts
await client.stopAll();
```

Stopping is also implicit when the client disconnects (server-side behavior).

## Patterns vs manual commands

| Approach | When to use |
| --- | --- |
| `device.vibrate(n)` | Immediate level, one-off changes |
| `PatternEngine.play()` | Loops, easing, presets, multi-track timing |

```ts
import { PatternEngine } from "@zendrex/buttplug.js/patterns";

const engine = new PatternEngine(client);
await engine.play(device, "wave", { intensity: 0.7, loop: true });
```

Pattern `intensity` is **0–1** and scales keyframe values, matching the device-method scale. See [Patterns](/docs/patterns).
