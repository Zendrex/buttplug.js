Library failures throw subclasses of [`ButtplugError`](/docs/client/errors). Use `instanceof` to branch on transport, device, and timeout cases.

```ts
import { ButtplugError, ConnectionError, DeviceError } from "@zendrex/buttplug.js";

try {
  await client.connect();
} catch (err) {
  if (err instanceof ConnectionError) {
    console.error("Could not reach server:", err.message);
  }
}
```

## Error hierarchy

All errors extend `ButtplugError`. Subclasses add fields such as `ProtocolError.code`, `DeviceError.deviceIndex`, and `TimeoutError.operation` / `timeoutMs`. Full class table: [Errors reference](/docs/client/errors).

## Narrowing in application code

Check specific subclasses before the base type:

```ts
try {
  await device.vibrate(0.5);
} catch (err) {
  if (err instanceof DeviceError) {
    console.error(`Device #${err.deviceIndex}: ${err.message}`);
  } else if (err instanceof TimeoutError) {
    console.error(`${err.operation} timed out after ${err.timeoutMs}ms`);
  } else if (err instanceof ButtplugError) {
    console.error(err.message);
  } else {
    throw err;
  }
}
```

## Protocol error codes

`ProtocolError.code` is one of [`ErrorCode`](/docs/client/constants#errorcode) (`UNKNOWN`, `INIT`, `PING`, `MESSAGE`, `DEVICE`). `PING` is terminal: the server has already stopped devices and dropped the connection.

```ts
import { ProtocolError, ErrorCode } from "@zendrex/buttplug.js";

if (err instanceof ProtocolError && err.code === ErrorCode.PING) {
  console.error("Ping timeout; reconnect rather than retry");
}
```

## Recovery patterns

### Connection lost

- Enable [`autoReconnect`](/docs/guide/connecting#auto-reconnect) for WebSocket apps.
- Listen for `connection.reconnected` and refresh UI state.
- On `connection.disconnected`, stop local timers and [`PatternEngine`](/docs/patterns) instances.

### Unsupported hardware

- Call `device.canOutput()` / `canRead()` / `canSubscribe()` before commands.
- Inspect `device.features` when building dynamic UIs.

### Slow operations

Increase `requestTimeout` on the client:

```ts
const client = new ButtplugClient("ws://127.0.0.1:12345", {
  requestTimeout: 30_000,
});
```

### Logging

```ts
import { formatError } from "@zendrex/buttplug.js";

try {
  await client.connect();
} catch (err) {
  console.error(formatError(err));
}
```

For protocol debugging in the browser, DevTools → Network → WebSocket → Messages is often more detailed than client logs.

## Events vs thrown errors

| Source | Mechanism |
| --- | --- |
| `await device.vibrate()` | Rejects promise (`DeviceError`, `TimeoutError`, …) |
| `connection.error` | Emitted for transport / protocol issues |
| `device.error` | Emitted for server-pushed `ErrorCode.DEVICE` |

Handle both in production apps: promises for command results, events for background failures.
