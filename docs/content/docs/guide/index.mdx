**buttplug.js** is a TypeScript client for the [Buttplug](https://buttplug.io) message protocol (v4). It validates wire messages with Zod, exposes typed [`Device`](/docs/client/device) instances, and works over WebSocket or an optional in-browser WASM server.

```ts
import { ButtplugClient } from "@zendrex/buttplug.js";

const client = new ButtplugClient("ws://127.0.0.1:12345");

client.on("device.added", async ({ data: { device } }) => {
  if (device.canOutput("Vibrate")) {
    await device.vibrate(0.5);
  }
});

await client.connect();
await client.startScanning();
```

## How it fits together

1. **Connect** to a Buttplug server ([Intiface Central](https://intiface.com/central/) over WebSocket, or [WASM + Web Bluetooth](/docs/guide/wasm) in the browser).
2. **Scan** for hardware; the client emits `device.added` for each match.
3. **Control** outputs (`vibrate`, `rotate`, `position`, …) and read sensors (`Battery`, `Button`, …).
4. **React** to lifecycle with typed events (`connection.*`, `device.*`, `scan.*`).
5. **Optional:** drive timed waveforms with the [`PatternEngine`](/docs/patterns) subpath.

Output values are normalized **0–1** floats; the library maps them to each feature's server-reported device range. The pattern engine uses the same **0–1** scale for intensities and keyframes; see [Patterns](/docs/patterns).

## Choose a connection path

| Path | Best for | You need |
| --- | --- | --- |
| **WebSocket** (default) | Node, Bun, Deno, desktop browsers | A v4 server such as Intiface Central (`ws://127.0.0.1:12345`) |
| **WASM transport** | Web apps without a desktop server | Chromium, HTTPS or `localhost`, peer [`buttplug-wasm-blob`](https://www.npmjs.com/package/buttplug-wasm-blob) |

Both paths share the same `ButtplugClient`, `Device` API, and events after `connect()`. Only transport setup differs.
