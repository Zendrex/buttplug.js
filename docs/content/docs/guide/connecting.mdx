[`ButtplugClient`](/docs/client/buttplug-client) owns the transport, protocol handshake, device list, and connection lifecycle. Everything else in the guide assumes a connected client.

```ts
import { ButtplugClient } from "@zendrex/buttplug.js";

const client = new ButtplugClient("ws://127.0.0.1:12345", {
  autoReconnect: true,
  maxReconnectAttempts: 10,
});

await client.connect();
```

`connect()` opens the transport and runs the v4 handshake. It resolves when the server accepts the session, or rejects with `ConnectionError` / `HandshakeError`.

## Transports

| Input | Transport | Typical use |
| --- | --- | --- |
| `string` URL | Built-in `WebSocketTransport` | Intiface Central, remote servers |
| `Transport` instance | Whatever you pass in | WASM, logging wrapper, tests |

### WebSocket (default)

```ts
const client = new ButtplugClient("ws://127.0.0.1:12345");
```

### Custom WebSocket transport

Inject a transport when you need extra options (for example a custom logger):

```ts
import {
  ButtplugClient,
  consoleLogger,
  WebSocketTransport,
} from "@zendrex/buttplug.js";

const transport = new WebSocketTransport("ws://127.0.0.1:12345", {
  logger: consoleLogger,
});

const client = new ButtplugClient(transport);
await client.connect();
```

### WASM (browser)

```ts
import { WasmTransport } from "@zendrex/buttplug.js/wasm";

const client = new ButtplugClient(new WasmTransport());
```

See [WASM Transport](/docs/guide/wasm) for peer dependencies, bundler notes, and browser constraints.

## Client options

| Option | Default | Purpose |
| --- | --- | --- |
| `clientName` | `"buttplug.js"` | Name sent during handshake |
| `autoPing` | `true` | Send periodic pings using the server interval |
| `autoReconnect` | `false` | Reconnect after unexpected disconnect (WebSocket only) |
| `reconnectDelay` | `1000` | Initial backoff delay (ms) |
| `maxReconnectDelay` | `30000` | Backoff cap (ms) |
| `maxReconnectAttempts` | `10` | Give up after this many failed attempts |
| `requestTimeout` | `10000` | Per-request timeout (ms) |
| `verbose` | `false` | Log to console when no `logger` is set |
| `logger` | `noopLogger` | Injectable diagnostics (`consoleLogger`, custom) |

Full option types: [`ButtplugClientOptions`](/docs/client/types#buttplugclientoptions).

## Keep-alive (ping)

Buttplug servers expect periodic pings. With `autoPing: true` (default), the client schedules pings from the interval returned in the handshake.

<Callout type="warn">
  If `autoPing` is `false`, you must send pings yourself. When the server's ping timer expires, it **stops all devices and disconnects** per the Buttplug specification.
</Callout>

## Auto-reconnect

`autoReconnect` applies to **WebSocket** transports only. An unexpected close triggers exponential backoff between attempts.

```ts
const client = new ButtplugClient("ws://127.0.0.1:12345", {
  autoReconnect: true,
  reconnectDelay: 1000,
  maxReconnectDelay: 30_000,
  maxReconnectAttempts: 5,
});

client.on("connection.reconnecting", ({ data: { attempt } }) => {
  console.log(`Reconnect attempt ${attempt}`);
});

client.on("connection.reconnected", () => {
  console.log("Back online; device list will refresh");
});
```

Full reconnect timeline (cached devices removed → reconcile → fresh `device.added`): [After reconnect](/docs/guide/events#after-reconnect-autoreconnect). Re-register command logic in `connection.reconnected` if you stopped patterns or timers on disconnect.

## Disconnect and cleanup

### Graceful disconnect

```ts
await client.disconnect("Session ended");
```

`disconnect()` stops devices on the server and closes the transport. An optional `reason` appears in `connection.disconnected`.

<Callout type="warn">
  Buttplug servers stop **all** devices when a client disconnects. That is server behavior; the client cannot override it.
</Callout>

### Dispose

When you are done with the client entirely:

```ts
await client.disconnect();
client.dispose();
```

`dispose()` removes listeners, stops keep-alive/reconnect, and clears internal state; call `disconnect()` first to close the transport. Further `connect()` or `play()` calls are invalid.
