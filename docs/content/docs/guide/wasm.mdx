The [`WasmTransport`](/docs/reference/wasm-transport) lets you skip Intiface Central entirely by embedding the Buttplug server in the page as WebAssembly. Hardware discovery uses **Web Bluetooth**, so the page must run in a Chromium-family browser over HTTPS (or `localhost`).

## When to use WASM

| | WebSocket + Intiface | WASM + Web Bluetooth |
| --- | --- | --- |
| **Runs in** | Any runtime with WebSockets | Chromium browsers only |
| **User installs** | Intiface Central (or another server) | Nothing extra |
| **Device discovery** | Server-side (USB, serial, BLE relay, etc.) | Browser Bluetooth picker only |
| **Best for** | Desktop apps, Node scripts, broad device support | Web apps, demos, mobile-friendly pages |

The device API (`Device`, events, commands) is identical once connected — only how you reach the server changes.

## Usage

Import `WasmTransport` from the `/wasm` subpath and pass it to `ButtplugClient` instead of a URL:

```ts
import { ButtplugClient } from "@zendrex/buttplug.js";
import { WasmTransport } from "@zendrex/buttplug.js/wasm";

const client = new ButtplugClient(new WasmTransport());

await client.connect();
await client.startScanning(); // browser prompts for a Bluetooth device

client.on("deviceAdded", async ({ data: { device } }) => {
  if (device.canOutput("Vibrate")) {
    await device.vibrate(0.5);
  }
});
```

`connect()` lazy-loads the WASM binary, initializes the in-process server, and resolves once the handshake completes. The WASM blob is only downloaded the first time you call `connect()`.

## Bundler setup

The base `@zendrex/buttplug.js` import does **not** pull in the WASM blob. The blob loads only when you import from `/wasm` and call `connect()`. Treat `@zendrex/buttplug.js/wasm` as a code-split boundary.

With **Vite**, pre-bundle the peer dependency so dev startup stays fast:

```ts
// vite.config.ts
import { defineConfig } from "vite";

export default defineConfig({
  optimizeDeps: {
    include: ["buttplug-wasm-blob"],
  },
});
```

The repo includes a runnable example — from the project root:

```bash
bun install
bun run example:wasm
```

Open `http://localhost:5173` in Chrome, click **Connect**, then **Scan** to pair a device through the Bluetooth prompt.

## Browser requirements

<Callout type="warn">
  Web Bluetooth is only available in Chromium-family browsers (Chrome, Edge, Opera) served from a **secure context** (HTTPS or `localhost`). Firefox and Safari throw `ConnectionError` on `connect()`.
</Callout>

The transport validates `navigator.bluetooth` before loading WASM and throws `ConnectionError` if unsupported.

## Limitations

- **No auto-reconnect** — `autoReconnect` on `ButtplugClient` only applies to WebSocket transports. In-process WASM has no network to lose; leave it disabled.
- **Bluetooth-only discovery** — devices must be pairable through the browser's Web Bluetooth picker. USB-only or server-relayed devices still need Intiface Central over WebSocket.
- **Bundle size** — the WASM binary is large; lazy-load the `/wasm` subpath and avoid importing it on pages that do not need direct device access.
